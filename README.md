# Dragon Forge X

> Инструмент для авторизованной разведки и аудита веб-приложений на Go.

[![Go](https://img.shields.io/badge/Go-1.22%2B-00ADD8?logo=go)](https://go.dev/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

## Важно: только с разрешением

Используйте Dragon Forge X **только** против систем, которыми вы владеете или на тестирование которых у вас есть явное письменное разрешение. Владелец проекта не несёт ответственности за незаконное или вредоносное использование.

Инструмент выполняет сетевые запросы, обнаружение маршрутов и, при включении активных модулей, тестовые запросы к целевой системе. Перед проверкой согласуйте область, время тестирования и допустимую нагрузку.

## Возможности

- пассивная HTTP-разведка и fingerprinting технологий;
- обнаружение маршрутов, форм, API и поддоменов;
- проверка HTTP-заголовков, CORS, CSP, OAuth и JWT;
- отчёты в JSON, SARIF и HTML;
- опциональные активные проверки типичных классов уязвимостей;
- опциональная интеграция с установленными `nmap` и `nuclei`.

Результаты проверки могут содержать чувствительные данные. Не загружайте их в публичный репозиторий.

## Требования

- Go 1.22 или новее;
- Windows, Linux или macOS;
- `nmap`/`nuclei` — только для опционального режима `--external`.

## Сборка

```bash
go build -trimpath -o dragon-forge-x .
```

## Быстрый старт

Пассивная проверка разрешённой цели:

```bash
./dragon-forge-x -u https://example.com -modules waf,recon,scan
```

Активные проверки включайте только после подтверждения разрешения:

```bash
./dragon-forge-x -u https://example.com -modules app,sqli,xss,csrf --active
```

Полный список параметров:

```bash
./dragon-forge-x -h
```

## Выходные файлы

По умолчанию результаты сохраняются в каталоге вида:

```text
<scheme>_<host>/result/
```

Там могут появиться `report.html`, `report.json`, `report.sarif`, логи и PoC-файлы. Эти каталоги намеренно исключены из Git через `.gitignore`.

## Ограничения

Это вспомогательный инструмент, а не замена ручной проверке. Возможны ложные срабатывания. Каждое finding необходимо подтвердить вручную и безопасным способом.

Перед публикацией результатов удалите:

- логины, пароли, токены и cookies;
- внутренние IP-адреса и домены;
- данные клиентов и сотрудников;
- содержимое `.env`, конфигураций и резервных копий;
- доказательства уязвимостей, если их раскрытие не согласовано.
